# 统一自动补货与遗物系统设计 — v3.0.0 原生版（修正）

## ⚠ 核心认知：v3.0.0 的残片是有限的

| 经济事实 | 数值 |
|:--------|:----:|
| 全游戏残片总量（一次性技术解锁） | **3,800** |
| 定向检索一次消耗 | 8 |
| 失败退回 | 2 |
| 分馏塔产残片 | **无** |
| 自动补货旧代码用的物品ID | 1099 = **I沙土**（不是IFE残片8161） |

这意味着旧 v2.3.0 的经济循环在 v3.0.0 中**全部断裂**。必须重新设计。

---

## 新设计：两个旧系统改造 + 补上残片经济链

不再假设"残片无限来自分馏塔"，而是让这两个系统**自己成为残片的来源**。

### 改造后核心循环

```
┌───────── 自动补货系统 ─────────┐
│  监测玩家生产线库存              │
│  → 自动卖出盈余                │
│  → 赚取的是金钱(COIN)/原版货币   │
│  → 自动买入短缺原料             │
│  (不再消耗IFE残片，用原版市场)    │
└──────────┬────────────────────┘
           │ 维持生产线稳定
           ▼
    分馏塔持续运转
           │
           ▼
    ┌─ 新增产出 ─────────┐
    │  每成功分馏一次       │
    │  → 概率产出IFE残片 x1 │
    │  (成功率越高产出越多)  │
    └──────────┬──────────┘
               │ 残片(8161)
               ▼
    ┌──── 玩家分配 ────┐
    │                  │
    ▼                  ▼
定向检索(协议)       遗物发掘
8残片/次            成本大幅降低
                    (从200~10000→2~20)
```

### 关键改动

#### 1. Auto Replenish → 改为原版市场交易

旧代码的问题：
- 用 `1099`（I沙土）做货币 → **Bug**
- 直接调 `AddItemToModData` 绕过了原版交易系统

改造：
- 用原版市场 API（`GameMain.mainPlayer.trade` 或 `GameMain.history`）
- 卖出赚**原版金币**，买入花**原版金币**
- 不再跟IFE残片挂钩
- 保留自动扫描、预算控制、白名单功能

#### 2. 分馏塔 → 概率产残片（新增，在 ProcessManager 中）

在 ProcessManager 每次成功分馏时，概率给残片：

```
每次成功分馏 →
    基础概率 15% 产 1 残片
    × 成功率加成（遗物/科技点）
    × 分馏塔等级加成

平均：每分钟几十到几百残片（取决于规模）
```

实现方式：在 `ProcessManager.cs` 的 success 处理链中添加一行。

#### 3. 遗物发掘 → 巨额降价

旧成本（200~10000）是 v2.3.0 时代分馏塔大量产残片时的定价，v3.0.0 必须调整：

| 时代 | 旧成本 | 新成本 | 解锁条件 |
|:----|:-----:|:------:|:--------|
| Primitive | 200~300 | **3** | 初始可用 |
| Ancient | 500~800 | **5** | 完成2个协议 |
| Classical | 1500~2500 | **10** | 完成5个协议 |
| Golden | 5000~10000 | **20** | 完成10个协议 |

保证玩家在正常流程中能负担得起全部16个遗物（总成本 ~152 残片 ≈ 19次定向检索的价值）。

#### 4. 遗物加成 → RecipeModifierCache

移除行星槽位，发掘即得全局加成：

```csharp
发掘遗物时 →
    RecipeModifierCache.AddAllRecipeSuccessRateBonus(遗物加成)
    // SpeedMultiplier → successRateBonus 换算
    // 例如 SpeedMultiplier=1.15 → +0.03 (3% 成功率)
    // SuccessBonus=0.05 → +0.05 (5% 成功率)
```

共鸣保留，但改为检测 `_discovered` 集合而非槽位：

```csharp
// 自动检测已收集的遗物是否满足共鸣条件
// 满足则额外加成
```

#### 5. 协议完成 → 免费发掘

保留之前已实现的逻辑：
- 协议完成 → +2 记忆源点（已有）
- 30% 概率免费发掘一次遗物（新）
- 深层解析 → +1 记忆源点 + 概率产残片
